

## Findings, most important first

1. **`\pdfoutput` is now a defined name, which conflicts with E8.** [core_latex.yaml:33–39](resources/bindings/engine/core_latex.yaml:33) adds it as "supported pdfTeX setup vocabulary" (commit 04677c7). That gives the name a meaning. E8 says pdfTeX names stay undefined, so a probe like `\ifx\pdfoutput\undefined` takes the "undefined" branch. The gauntlet fixture has exactly that probe in case D1, at [gmvenue.cls:25–29](tests/fixtures/specimens/gauntlet-master/gmvenue.cls:25) and `sections/branches.tex:4`. Defining the name aligns the engine with the Tectonic oracle, which also defines `\pdfoutput`, but the trade-off was never decided. It can be avoided: let preparation read the extent of `\pdfoutput=1` so it can preserve the statement, without installing a meaning that `\ifx` and `\ifdefined` would see.

2. **A latent bug: an active character can pick up a control symbol's meaning.** [expansion.py:156–157](src/engine/expansion.py:156) and [integers.py:48–49](src/engine/integers.py:48) call `knowledge.resolve_command(token.value)` for any token that has no recorded meaning. `resolve_command` puts a backslash in front of the spelling, so an active `~` would resolve to the profile of the accent `\~`. The dispatcher guards against this at [dispatcher.py:428](src/reading/dispatcher.py:428), but the engine doesn't. Nothing triggers it yet, but it will once a control symbol whose spelling matches an active character gets bound. The fix is to consult knowledge only for control-sequence tokens, and to return a requirement for an active character with no meaning.

3. **The engine's dispatch still runs on YAML family strings.** The docstring of [reading/operations.py](src/reading/operations.py) says the adapter keeps the prototype vocabulary out of the engine. Yet the host passes the family-keyed `FAMILY_OPERATIONS`, the engine calls `operations.get(profile.family)` ([expansion.py:163](src/engine/expansion.py:163), [integers.py:51](src/engine/integers.py:51)), and it also checks `grammar["handler"] == "primitive_definition"` and `profile.name == r"\relax"` ([expansion.py:168–170](src/engine/expansion.py:168)). A cleaner contract is a single host method that resolves a meaning to its operation, with the engine reading only that operation's roles. `\relax` and the primitive `\def` would then be ordinary `unexpandable=True` operations instead of special cases.

4. **The `reading` and `engine` packages import each other.** `reading/context.py` imports `engine.parameters`, and engine modules import widely from `reading.*`. That's harmless today, but it means the engine can't be built or tested on its own. Brief §9.2 makes `EngineState` the evolved `ReaderContext`, which points to state living in `engine` with `reading` importing from it, not both ways.

5. **Minor: `\let` isn't marked unexpandable.** Inside an `\edef` body, `meaning.assign` reaches the `expansion_required` boundary, where TeX would keep `\let` as an unexpanded token. It's conservative, a boundary rather than wrong output, but it stops common restore idioms such as `\edef\x{\let\noexpand\a\noexpand\b}`.

6. **Worth watching: probe cost.** In source-command mode, every occurrence of a stored macro gets a `package_request` probe ([dispatcher.py ~420](src/reading/dispatcher.py:420)). Each failed probe can spend up to the 10,000-step budget before restoring, and nothing is cached. It's correct, but it could get slow on papers that use many macros.
